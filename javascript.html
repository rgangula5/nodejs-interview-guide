1 · Types, Coercion & Equality

Primitive types?

string, number, bigint, boolean, undefined, null, symbol — plus object (non-primitive). Primitives are immutable and copied by value; objects by reference.

null vs undefined?

undefined = declared but not assigned (JS default). null = intentional "no value" (you set it). typeof undefined === 'undefined'; typeof null === 'object' (historic bug).

== vs ===?

=== strict — no type coercion. == loose — coerces types first. Always use === unless you deliberately want coercion. null == undefined is true; null === undefined is false.

Truthy / falsy?

Falsy: false, 0, -0, 0n, "", null, undefined, NaN. Everything else (incl. "0", [], {}) is truthy.

NaN?

"Not a Number"; typeof NaN === 'number'; NaN !== NaN — check with Number.isNaN(x).

[] == ![]      // true  (![] -> false -> 0; [] -> "" -> 0)
'5' + 3        // '53'  (string concat)
'5' - 3        // 2     (numeric)
0.1 + 0.2      // 0.30000000000000004 (float precision)

2 · Scope, Hoisting, var/let/const

  • var — function-scoped, hoisted & initialized to undefined, re-declarable.
  • let/const — block-scoped, hoisted but in the Temporal Dead Zone (can't use before declaration), not re-declarable. const can't be reassigned (but object contents can still mutate).

What is hoisting?

Declarations are moved to the top of their scope at compile time. var and function declarations are hoisted (var → undefined; function → fully). let/const are hoisted but not initialized (TDZ). Function expressions are not hoisted as functions.

console.log(a); // undefined  (var hoisted)
var a = 1;
console.log(b); // ReferenceError (TDZ)
let b = 2;

3 · Closures

A closure is a function that remembers the variables from the scope where it was created, even after that scope has returned. Used for data privacy, factories, memoization, callbacks.

function counter() {
  let count = 0;               // private
  return () => ++count;        // closes over count
}
const c = counter();
c(); // 1
c(); // 2

The classic loop bug

for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0 1 2

var is one shared binding (all callbacks see the final i=3); let creates a fresh binding per iteration.

4 · this & Binding

this is determined by how a function is called, not where it's defined:

  • Default — plain call → global object (or undefined in strict mode).
  • Implicit — obj.method() → this = obj.
  • Explicit — call/apply (invoke now) / bind (return bound fn) set this.
  • new — this = the new object.
  • Arrow functions — no own this; they inherit it lexically from the enclosing scope. (Can't be bound; not usable as constructors.)
const obj = {
  name: 'A',
  regular() { return this.name; },        // 'A'
  arrow: () => this?.name,                 // NOT obj — lexical this
};
const f = obj.regular;
f();                 // undefined/global (lost binding)
obj.regular.call({name:'B'}); // 'B'
Say this: "this depends on the call site. Arrow functions don't have their own this — they capture it lexically, which is why they're great for callbacks but wrong for object methods/constructors."

5 · Prototypes & Inheritance

Every object has an internal link ([[Prototype]], accessed via __proto__) to another object. Property lookups walk this prototype chain until found or null. This is how JS does inheritance.

  • Func.prototype — the object that instances created with new Func() inherit from.
  • obj.__proto__ — the actual prototype of an instance (= its constructor's .prototype).
  • class is syntactic sugar over prototypes; extends/super set up the chain.
class Animal { speak(){ return 'generic'; } }
class Dog extends Animal { speak(){ return 'woof'; } }
new Dog().speak();               // 'woof'
new Dog() instanceof Animal;     // true

6 · Functions (HOF, currying, arrow)

  • First-class — functions are values (pass, return, store).
  • Higher-order function — takes/returns a function (map, filter, middleware).
  • Currying — f(a)(b)(c) — transform a multi-arg fn into a chain of single-arg fns.
  • Arrow vs regular — arrow: lexical this, no arguments, can't be new'd, concise. Regular: dynamic this, has arguments.
  • Params — default (=), rest (...args), spread on call.
const add = a => b => a + b;   // curried
add(2)(3); // 5
const sum = (...nums) => nums.reduce((a,b)=>a+b, 0); // rest
sum(1,2,3); // 6

7 · The Event Loop & Async (JS side)

JS is single-threaded with a call stack. Async work (timers, fetch, I/O) is handled by the environment (browser/Node); when done, callbacks go to queues the event loop drains when the stack is empty.

  • Microtask queue — Promises (.then), queueMicrotask, MutationObserver. Drained fully after each task, before rendering.
  • Macrotask (task) queue — setTimeout, setInterval, I/O, UI events.

Rule: after each macrotask, ALL microtasks run before the next macrotask. So a Promise callback always beats a setTimeout(...,0).

console.log('A');
setTimeout(() => console.log('B'), 0);
Promise.resolve().then(() => console.log('C'));
console.log('D');
// A  D  C  B   (sync -> microtasks -> macrotasks)

8 · Promises & async/await

  • A Promise is pending → fulfilled/rejected (settles once). .then/.catch/.finally.
  • async fn returns a Promise; await pauses until it settles.
  • Combinators: all (all or first-reject), allSettled (all, never rejects), race (first settle), any (first fulfill).
// sequential (slow) vs parallel (fast)
const a = await getA(); const b = await getB();      // slow
const [a, b] = await Promise.all([getA(), getB()]);  // fast

// error handling
try { await risky(); } catch (e) { /* handles rejection */ }
Gotcha: array.forEach(async ...) does NOT wait. Use for...of + await (sequential) or Promise.all(array.map(...)) (parallel).

9 · Objects, Arrays, Copying

Shallow vs deep copy

const shallow = { ...obj };            // or Object.assign({}, obj)
const shallowArr = [...arr];           // top level only
const deep = structuredClone(obj);     // true deep copy (modern)
// JSON.parse(JSON.stringify(obj)) - deep but loses fns/dates/undefined

Shallow copies share nested references — mutating a nested object affects both. Deep copy fully clones.

Key array methods

map (transform), filter (subset), reduce (fold to one value), find/findIndex, some/every, forEach (side effects), flat/flatMap, sort (mutates!), slice (copy) vs splice (mutate).

[1,2,3,4].filter(n => n%2===0).map(n => n*10); // [20,40]
[1,2,3].reduce((sum,n) => sum+n, 0);           // 6

Destructuring & optional chaining

const { name, age = 18 } = user;      // default
const [first, ...rest] = arr;
const city = user?.address?.city;     // optional chaining
const val = input ?? 'default';       // nullish (only null/undefined)

10 · ES6+ Features (know these names)

  • let/const, arrow functions, template literals `${x}`.
  • Destructuring, spread/rest, default params.
  • Classes, modules (import/export).
  • Map / Set (and Weak variants), Symbol.
  • Promises, async/await, generators (function*, yield).
  • Optional chaining ?., nullish coalescing ??.
  • Object.entries/values/keys, Array.flat/flatMap, String.padStart.

Map vs Object?

Map: any key type, ordered, easy size (.size), better for frequent add/remove. Object: string/symbol keys, JSON-friendly, has prototype. Set = unique values.

12 · Rapid-Fire Q&A (50+)

== vs ===?

Loose (coerces) vs strict (no coercion). Prefer ===.

null vs undefined?

Intentional empty vs not-yet-assigned.

typeof null?

'object' (legacy bug).

Falsy values?

false, 0, -0, 0n, '', null, undefined, NaN.

Check for NaN?

Number.isNaN(x); NaN !== NaN.

var vs let vs const?

Function-scoped/hoisted vs block-scoped/TDZ; const no reassignment.

What is hoisting?

Declarations moved to top of scope; var→undefined, let/const→TDZ.

TDZ?

Temporal Dead Zone — can't access let/const before declaration.

What is a closure?

A function remembering its outer scope after that scope returns.

Closure use cases?

Data privacy, factories, memoization, callbacks/currying.

How is `this` determined?

By the call site: default/implicit/explicit(call,apply,bind)/new; arrow = lexical.

call vs apply vs bind?

call(args), apply([args]) invoke now; bind returns a new bound function.

Arrow vs regular function?

Arrow: lexical this, no arguments, not constructable, concise.

Prototype chain?

Lookup walks __proto__ links until found or null — JS inheritance.

prototype vs __proto__?

Constructor's .prototype vs an instance's actual prototype link.

class in JS?

Syntactic sugar over prototypes.

First-class functions?

Functions are values — pass/return/store them.

Higher-order function?

Takes or returns a function.

Currying?

Turn f(a,b,c) into f(a)(b)(c).

IIFE?

Immediately-invoked function expression — creates a private scope.

Event loop in one line?

Runs queued callbacks when the call stack is empty.

Microtask vs macrotask?

Promises (micro) drain fully before the next timer/task (macro).

Promise vs setTimeout(0)?

Promise (microtask) runs first.

Promise states?

Pending → fulfilled/rejected; settles once.

all vs allSettled vs race vs any?

all: all/first-reject; allSettled: all, never rejects; race: first settle; any: first fulfill.

async function returns?

Always a Promise.

await does what?

Pauses the async fn until the promise settles.

forEach + async trap?

Doesn't await; use for...of or Promise.all(map).

Sequential vs parallel awaits?

Separate awaits = sequential; Promise.all = parallel.

Shallow vs deep copy?

Spread copies top level; structuredClone deep-clones.

Spread vs rest?

Spread expands; rest gathers into an array.

map vs forEach?

map returns a new array; forEach returns undefined (side effects).

reduce?

Folds an array into a single value with an accumulator.

slice vs splice?

slice copies (no mutate); splice mutates (add/remove).

Optional chaining?

?. safely accesses nested props; short-circuits on null/undefined.

Nullish coalescing?

?? defaults only on null/undefined (not 0/''/false).

Map vs Object?

Any key type, ordered, .size vs string keys/JSON-friendly.

Set?

Collection of unique values.

Symbol?

Unique immutable primitive, often for unique object keys.

Generator?

function* that can pause/resume via yield.

Object.freeze?

Shallow-immutable object (top-level props can't change).

const with objects?

Binding is constant, but the object's contents can still mutate.

Pass by value or reference?

Primitives by value; objects by reference (the reference itself is passed by value).

== null trick?

x == null is true for both null and undefined.

Debounce vs throttle?

Debounce: run after quiet period; throttle: run at most once per interval.

JSON.stringify limitations?

Drops functions/undefined, mangles dates, fails on circular refs.

Truthy [] and {}?

Both are truthy (only listed falsy values are false).

'5' + 3 vs '5' - 3?

'53' (concat) vs 2 (numeric coercion).

Deep equality of objects?

=== compares references; deep-compare by value manually or with a lib.

13 · Deep-Dive Follow-ups (layer 2 & 3)

The chains interviewers actually push you through after your first answer.

Closures → ↳ Do closures cause memory leaks?

They can — a closure keeps its referenced variables alive, so a long-lived closure (e.g., an event listener) holding a large object prevents GC. Fix: remove listeners, null references you no longer need.

↳ ↳ How is that different from a normal variable being collected?

Normally a variable is GC'd when its scope exits and nothing references it. A closure extends that lifetime by keeping a reference, so it survives until the closure itself is unreachable.

↳ Real-world closure uses beyond counters?

Module pattern (private state), memoization caches, once() wrappers, partial application/currying, event handlers capturing context, React hooks (useState closes over state).

this → ↳ Why do arrow functions fix the "lost this" in callbacks?

Arrows have no own this; they capture it lexically at definition. So setTimeout(() => this.x) inside a method keeps the method's this, whereas a regular function would get the default/global.

↳ ↳ Then why are arrows WRONG for object methods?

Because they capture this from the surrounding (module/global) scope, not the object — so { name, greet: () => this.name } won't see this.name.

↳ How would you implement bind yourself?

Function.prototype.myBind = function(ctx, ...pre) {
  const fn = this;
  return function(...rest) { return fn.apply(ctx, [...pre, ...rest]); };
};

Event loop → ↳ Trace this with await:

async function f(){ console.log(1); await null; console.log(2); }
console.log('A'); f(); console.log('B');
// A 1 B 2   (code after await is a microtask)

↳ ↳ Can microtasks starve the event loop?

Yes — a microtask that keeps queuing more microtasks (or recursive process.nextTick) can prevent timers/I-O from ever running. That's why nextTick recursion is dangerous.

↳ Browser vs Node event loop difference?

Concept is the same. Node adds process.nextTick (runs before other microtasks) and distinct libuv phases (timers/poll/check); browsers add rendering between tasks and have their own task sources (UI events).

Prototypes → ↳ Difference between __proto__ and prototype, precisely?

Ctor.prototype is the object future instances will inherit from. instance.__proto__ is the live link on an instance, equal to its constructor's .prototype. Only functions have .prototype; all objects have __proto__.

↳ ↳ How does instanceof actually work?

It walks the object's prototype chain checking whether Ctor.prototype appears in it.

↳ hasOwnProperty vs in?

in checks the whole chain (incl. inherited); hasOwnProperty checks only the object's own keys.

Promises → ↳ What happens to an unhandled rejection?

It triggers unhandledRejection (Node) / a console error (browser); in Node it can crash the process. Always attach .catch or wrap in try/catch.

↳ ↳ Run promises sequentially over an array?

await arr.reduce(async (p, item) => { await p; await handle(item); }, Promise.resolve());
// or a simple for...of with await

↳ Can you cancel a Promise?

Not natively — a Promise can't be cancelled once started. Use an AbortController/signal (fetch supports it) or a cancellation flag the async work checks.

Copying → ↳ Why is JSON.parse(JSON.stringify()) a bad deep clone?

It drops undefined/functions/symbols, turns Date into a string, loses Map/Set, and throws on circular references. Use structuredClone (handles most, incl. circular) — though it still can't clone functions.

↳ Object.is vs ===?

Mostly same, but Object.is(NaN, NaN) is true and Object.is(+0,-0) is false (=== gives the opposite).

Debounce vs throttle → ↳ Implement debounce.

function debounce(fn, ms){ let t; return (...a)=>{ clearTimeout(t); t=setTimeout(()=>fn(...a), ms); }; }

↳ ↳ When throttle instead?

Debounce = wait until activity stops (search-as-you-type). Throttle = run at most once per interval regardless (scroll/resize handlers).

Master these first: closures · this & arrow functions · event loop (micro vs macro) · Promises/async-await · hoisting & TDZ · coercion (== vs ===). They're asked in nearly every JS interview.
