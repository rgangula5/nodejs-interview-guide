1 · Why TypeScript & How It Works

What is TypeScript and why use it?

A typed superset of JavaScript that compiles to plain JS. It adds a static type system checked at compile time, giving early error detection, better tooling/autocomplete, safer refactors, and self-documenting code.

↳ Does TypeScript do anything at runtime?

No. Types are fully erased during compilation — the emitted JS has no type info. So you can't do runtime checks based on TS types (e.g., you can't reflect an interface). Runtime validation still needs actual JS checks or a library like Zod.

↳ Then how does it catch errors?

The compiler (tsc) statically analyzes your code against the types before emitting JS. If it doesn't type-check, you get a compile error — but (by default) it still emits JS unless noEmitOnError is set.

↳ What is "structural typing" (and how does it differ from Java/C#)?

TS uses structural ("duck") typing: compatibility is based on an object's shape, not its declared name. If it has the required members, it fits — even if it never declared it implements the type. Java/C# use nominal typing (must explicitly declare the relationship).

2 · any / unknown / never / void

Explain any, unknown, never, void.

  • any — opts out of type checking; anything goes. Avoid — it silently disables safety.
  • unknown — the type-safe any; you can hold anything but must narrow/check before using it.
  • never — a value that never occurs (a function that always throws or infinite-loops; the type of exhaustiveness checks).
  • void — a function returns nothing meaningful (undefined).

↳ any vs unknown — concrete difference?

Both accept any value, but any lets you do anything with it (no checks); unknown forces you to narrow first:

let a: any = getData();     a.foo.bar();     // compiles, may crash
let u: unknown = getData(); u.foo;           // ERROR
if (typeof u === 'object' && u) { /* now safe */ }

↳ Where is never actually useful?

Exhaustiveness checking on a union — if you handle every case, the "default" is never; add a new case and TS errors:

function area(s: Shape) {
  switch (s.kind) {
    case 'circle': return ...;
    case 'square': return ...;
    default: const _exhaustive: never = s; return _exhaustive; // errors if a case is missed
  }
}

↳ Difference between void and undefined?

undefined is a specific value; void means "ignore the return value." A () => void callback may actually return something — TS just ignores it (useful so arr.forEach(x => arr2.push(x)) is allowed even though push returns a number).

3 · type vs interface

When do you use type vs interface?

Both describe object shapes and are mostly interchangeable. interface — for object/class contracts; supports declaration merging and extends. type — more flexible: unions, intersections, primitives, tuples, mapped/conditional types.

↳ Name concrete things one can do that the other can't.

type can be a union / tuple / primitive alias / conditional / mapped type — interface cannot. interface supports declaration merging (declare it twice, they merge) — type cannot (duplicate = error).

type ID = string | number;          // union - only type can do this
interface Box { w: number; }
interface Box { h: number; }        // merges -> { w; h }  (only interface)

↳ Which should a library expose publicly, and why?

Often interface for public object/API contracts — because consumers can augment it via declaration merging (extending third-party types). Use type for unions/complex compositions. Teams commonly standardize on one for consistency.

↳ Can both extend?

Yes. interface B extends A {}; type B = A & { ... } (intersection). Interfaces can extend types and vice versa in most cases.

4 · Union, Intersection, Literal & Narrowing

Union vs intersection?

Union A | B = value is one of the types (you can only use members common to all). Intersection A & B = value has all members of both.

↳ Why can't I access b.name on a A | B directly?

On a union you may only use members that exist on every member of the union. To access type-specific members you must narrow first (typeof / in / discriminant).

↳ What are literal types and why useful?

A type that is an exact value: type Dir = 'up' | 'down'. Gives you enum-like safety with plain strings — great for discriminated unions and API contracts.

5 · Type Guards & Discriminated Unions

How do you narrow types?

typeof (primitives), instanceof (classes), in (property presence), truthiness, equality, and user-defined type guards.

↳ Write a user-defined type guard.

function isCat(a: Cat | Dog): a is Cat {   // "type predicate"
  return (a as Cat).meow !== undefined;
}
if (isCat(animal)) animal.meow();          // narrowed to Cat

↳ What's a discriminated (tagged) union and why is it the best pattern?

A union of object types sharing a common literal field (the discriminant). Switching on it narrows automatically and enables exhaustiveness checks:

type Shape =
  | { kind: 'circle'; r: number }
  | { kind: 'square'; side: number };
function area(s: Shape) {
  switch (s.kind) {                 // TS narrows by 'kind'
    case 'circle': return Math.PI * s.r ** 2;
    case 'square': return s.side ** 2;
  }
}

↳ What's an assertion function?

A function that throws if a condition fails and narrows afterward: function assert(c: unknown): asserts c { if (!c) throw new Error(); }. After assert(x), TS treats x as truthy.

6 · Generics

What are generics and why?

Type parameters that let a function/class/type work over many types while preserving type information (vs any, which loses it).

function identity<T>(x: T): T { return x; }
const n = identity(5);      // T = number, return type number

↳ Generic vs any — why not just use any?

any discards the type (return is any); a generic links input and output types, keeping full safety and autocomplete downstream.

↳ What are generic constraints?

function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;   // T must have .length
}

↳ Explain keyof and a generic getter.

function get<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];   // return type is the property's type
}
get({a:1,b:'x'}, 'b'); // typed as string

↳ What is infer (preview)?

Used in conditional types to extract a type. e.g., type ElementOf<T> = T extends (infer U)[] ? U : never; — pulls the element type out of an array type. (More in §8.)

7 · Utility Types (know these cold)

  • Partial<T> — all props optional. Required<T> — all required.
  • Readonly<T> — all props readonly.
  • Pick<T,K> — subset of keys. Omit<T,K> — all but those keys.
  • Record<K,V> — object with keys K and values V.
  • Exclude<U,X> / Extract<U,X> — filter a union.
  • NonNullable<T> — remove null/undefined.
  • ReturnType<F>, Parameters<F>, Awaited<T> — extract from functions/promises.

↳ Implement Partial<T> yourself (very common ask).

type MyPartial<T> = { [K in keyof T]?: T[K] };

↳ Implement Pick and Omit.

type MyPick<T, K extends keyof T> = { [P in K]: T[P] };
type MyOmit<T, K extends keyof T> = MyPick<T, Exclude<keyof T, K>>;

↳ Difference between Record<string, X> and an index signature?

Nearly equivalent; Record is a cleaner alias for { [k: string]: X } and can also take a union of literal keys (Record<'a'|'b', number>) to require exactly those keys.

8 · Advanced: Conditional, Mapped, Template, infer

Mapped types

type Optional<T> = { [K in keyof T]?: T[K] };       // map over keys
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };

Conditional types + infer

type IsString<T> = T extends string ? true : false;
type Unwrap<T> = T extends Promise<infer U> ? U : T;   // infer extracts U
type Elem<T> = T extends (infer U)[] ? U : never;

Template literal types

type Route = `/api/${string}`;
type Event = `on${Capitalize<'click' | 'hover'>}`;  // 'onClick' | 'onHover'

↳ What does the as clause do in a mapped type?

Key remapping — rename or filter keys while mapping (e.g., prefix keys with get, or drop keys by mapping to never).

↳ What is a distributive conditional type?

When the checked type is a naked type parameter and you pass a union, the conditional distributes over each member: type NonNull<T> = T extends null|undefined ? never : T applied to string|null gives string.

9 · Enums & const assertions

Enums — pros/cons?

Named constants. Numeric enums auto-increment; string enums are explicit. Caveat: regular enums emit runtime JS objects (not fully erased) and have quirks — many teams prefer union of string literals or as const objects.

↳ Why do some teams avoid enums?

They generate runtime code (bigger bundles), numeric enums are loosely typed (any number assignable in some cases), and const enum has its own inlining/tooling caveats. A union type 'A' | 'B' is purely compile-time and simpler.

↳ What does as const do?

const dirs = ['up','down'] as const;  // readonly tuple of literals, type 'up'|'down'
type Dir = typeof dirs[number];        // 'up' | 'down'

as const makes literals readonly and narrows them to their exact literal types instead of widening (e.g., string).

10 · Classes & Access Modifiers

  • public (default), private (class only), protected (class + subclasses).
  • readonly — set once (in declaration/constructor).
  • Parameter properties — declare + assign in the constructor signature: constructor(private id: string) {}.
  • abstract classes/methods — can't instantiate; must be implemented by subclass.
  • implements — a class conforms to an interface (structural).

↳ TS private vs JS #private — difference?

TS private is compile-time only — erased, accessible at runtime via bracket access. JS #field is truly private at runtime (hard privacy). Use # when you need real encapsulation.

↳ abstract class vs interface — when each?

Interface = pure contract, no implementation, multiple can be implemented. Abstract class = partial implementation + shared state + forces subclasses to implement abstract members; single inheritance.

11 · Functions, Overloads, this

// overloads: multiple signatures, one implementation
function parse(x: string): object;
function parse(x: number): string;
function parse(x: any): any { /* ... */ }

↳ Function type vs call signature?

type Fn = (a: number) => string. You can also add call signatures to an interface (a callable object with properties).

↳ Covariance/contravariance of parameters (advanced)?

Function parameter types are checked bivariantly by default (contravariantly under strictFunctionTypes). Interview-safe phrasing: "return types are covariant, parameters are contravariant under strict function types."

12 · Modules, .d.ts, tsconfig strictness

  • .d.ts — declaration files: types only, no implementation; describe JS libs (@types/*) or ambient globals (declare).
  • tsconfig — strict turns on the safety suite: noImplicitAny, strictNullChecks, strictFunctionTypes, etc.

↳ What does strictNullChecks change?

Without it, null/undefined are assignable to everything (unsafe). With it, they're separate types you must handle explicitly — the single most valuable strict flag.

↳ Type assertion (as) vs type casting?

TS "casting" (x as T) is a compile-time assertion — it tells the compiler "trust me," does no runtime conversion, and can be unsafe. Prefer narrowing/guards over assertions.

↳ Non-null assertion !?

value!.foo tells TS "this isn't null/undefined." Compile-time only; wrong assertion → runtime crash. Use sparingly.

13 · Rapid-Fire Q&A (40+)

Is TS runtime or compile-time?

Compile-time; types are erased, no runtime effect.

Structural vs nominal typing?

TS is structural — compatibility by shape, not name.

any vs unknown?

any disables checks; unknown forces narrowing before use.

When is never used?

Functions that never return; exhaustiveness checks.

void vs undefined?

void = ignore the return; undefined = a specific value.

type vs interface?

interface: merging + OO contracts; type: unions/tuples/mapped/conditional.

Can interface do unions?

No — only type can.

Declaration merging?

Multiple interface declarations with the same name combine.

Union vs intersection?

One-of vs has-all.

Literal type?

Exact value type, e.g. 'up' | 'down'.

How to narrow?

typeof, instanceof, in, equality, user-defined guards.

Type predicate?

`arg is Type` return type — a user-defined type guard.

Discriminated union?

Union sharing a literal tag; enables auto-narrowing + exhaustiveness.

Assertion function?

`asserts x` — throws or narrows.

Generics — why?

Reuse with types preserved (unlike any).

Generic constraint?

`T extends Shape` limits what T can be.

keyof?

Union of an object's keys.

T[K] (indexed access)?

The type of property K on T.

infer?

Extracts a type inside a conditional type.

Mapped type?

`{ [K in keyof T]: ... }` — transform each property.

Conditional type?

`T extends U ? X : Y`.

Template literal type?

Build string literal types, e.g. `/api/${string}`.

Partial/Required?

All optional / all required.

Pick/Omit?

Keep / drop selected keys.

Record<K,V>?

Object with keys K, values V.

Exclude/Extract?

Filter a union out / in.

ReturnType/Parameters?

Extract a function's return/param types.

Awaited<T>?

Unwraps a Promise's resolved type.

as const?

Readonly + narrow to literal types.

Enum downside?

Emits runtime code; unions are purely compile-time.

private (TS) vs #private (JS)?

Compile-time only vs true runtime privacy.

Parameter properties?

Declare+assign a field in the constructor signature.

abstract vs interface?

Partial impl + state vs pure contract.

implements?

Class conforms to an interface (structural).

Function overloads?

Multiple signatures, one implementation.

strictNullChecks?

Makes null/undefined explicit types you must handle.

as (assertion)?

Compile-time "trust me"; no runtime conversion.

Non-null assertion !?

Asserts value isn't null/undefined (unsafe if wrong).

.d.ts file?

Type declarations only; describes JS libs / ambient types.

unknown in a catch?

In strict mode `catch (e)` is unknown — narrow before use.

Index signature?

`{ [k: string]: T }` for dynamic keys.

Does TS guarantee runtime safety?

No — only compile-time; external data still needs runtime validation (e.g., Zod).
